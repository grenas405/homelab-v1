Reading the setup script

You ran setup.sh once. This plate opens it up so the run stops being magic: what each step does, how to preview it safely, and the handful of bash ideas it's built from.

What it installs, in order

The script is a guided sequence. It narrates itself as it goes, with cyan step headers and violet "Homelab note" lines — those notes are the same explanations, live, that this handbook expands on.

  1. A safety prompt. A banner names the target machine — Eric Harvey's Workstation — and makes you type yes before it changes anything. This exists so the script can't be run on the wrong box by reflex.
  2. Step 1 — Ollama. Installs the Ollama server, registers it as a service, and waits until localhost:11434 answers before moving on.
  3. Step 2 — the model. ollama pull qwen3:8b, skipped if you already have it.
  4. Step 3 — a clean Python environment. Removes any old ~/openwebui-env so the install starts fresh.
  5. Step 4 — Python itself. Uses system Python 3.12 if available; otherwise builds 3.11 from source with pyenv. Open WebUI needs one of those.
  6. Step 5 — Open WebUI. Creates the virtual environment and pip install open-webui into it.
  7. The hardware report. Prints the GPU and CPU/RAM tables from Plate 04, then the VRAM rule of thumb.

Preview it first: --dry-run

The script takes a --dry-run flag. In that mode it walks every step and prints the whole narration — banner, step headers, notes, and the real hardware report — but installs nothing and changes no files. Each action it would take is shown as a ~ would run: line. Flip the toggle to compare.

setup.sh — Step 1 

        

        

      


      
Use --dry-run to read what a script will do before you let it touch your machine
      — a good habit for any install script, not just this one. ./setup.sh --help lists the
      options.


      
It's safe to run again

      
Most of the script checks before it acts: it skips Ollama if the command already exists, skips the
      model if ollama list shows it, and re-uses a working Python. Re-running after a failed or
      interrupted run generally just picks up where it left off. Step 3 always rebuilds the Open WebUI
      environment from scratch — cheap, and it avoids half-installed states.

        The one-line version
        setup.sh is a narrated, mostly re-runnable sequence: confirm the machine, install Ollama +

You're set up

      
That's the stack. Ollama runs models on :11434. Open WebUI gives you a chat screen on
      :8080 — start it with source ~/openwebui-env/bin/activate then
      open-webui serve. The hardware report tells you what size model your box will run well. If
      something breaks, Plate 02's health check is the first move.


      

        
Self-check


        

          
1. A colleague sends you an unfamiliar install.sh. Best first move?

          
          
          
          
          
Reading an install script before running it is the habit. A dry-run mode, when it
          exists, shows the intended actions without making them.

        


        

          
2. Step 1 finishes installing Ollama but the script stops before pulling the model, saying the API
          didn't respond. What is it waiting on?

          
          
          
          
          
The script polls localhost:11434 and only proceeds once the server
          answers, so it doesn't try to pull a model into a server that isn't ready.

        


        

          
3. You run ./setup.sh a second time, a week later. What happens to qwen3:8b?

          
          
          
          
          
Step 2 checks whether the model is already present and skips the multi-gigabyte
          download if so. Re-running the script is safe.
