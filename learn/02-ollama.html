The engine room — Ollama

Ollama is the piece that actually runs the model. It sits in the background as a server, and everything else — Open WebUI, the ollama command, your own scripts — is a client that talks to it.

A server you don't usually see

When setup.sh installed Ollama, it also registered a service: a program the system keeps running in the background and restarts after a reboot, without anyone logging in. That service is the Ollama server. It loads models into memory, runs them, and answers requests.

You talk to it two ways:

  • The ollama command in a terminal — a thin client that sends your request to the server and prints the response.
  • An HTTP API at http://localhost:11434 — the same door Open WebUI knocks on for every message you send.
localhost and :11434 localhost is the machine talking to itself — a request to localhost never leaves the workstation. 11434 is a port: a numbered door on that machine. Ollama listens at door 11434; Open WebUI listens at door 8080. Different doors, same building.

Checking it's alive

Two quick ways to confirm the server is up. setup.sh uses the second one during installation, polling until it answers before it tries to pull a model.

$ ollama ps
NAME        ID    SIZE    PROCESSOR    UNTIL
(empty — server is up, no model loaded yet)

$ curl -s http://localhost:11434/api/tags
{"models":[ ... ]}

Where the models live

      
Downloaded models sit under ~/.ollama/models. They are large and they add up: a Q4 8B
      model is 5–6 GB, a 70B model is 40 GB. ollama list shows what you have;
      ollama rm <name> deletes one when you need the disk back. Removing a model does not
      uninstall Ollama — you can always pull it again.


      
A Modelfile changes a model's defaults

      
A Modelfile is a short recipe that takes an existing model and bakes in different
      defaults — a system prompt, a temperature, a context size — then saves it under a new name.
      You rarely need one early on, but it's how "give me a version of qwen3 that always answers as a terse
      shell assistant" is done without repeating yourself.

      
# file: Modelfile
FROM qwen3:8b
PARAMETER temperature 0.4
SYSTEM "You are a terse assistant for a Linux workstation. Prefer commands over prose."

$ ollama create shell-helper -f Modelfile
$ ollama run shell-helper


      

        The one-line version
        Ollama is a background server that runs models and answers on localhost:11434. You drive
        it with pull, run, list, ps, and rm.
        Open WebUI is just another client of that same server.
      


      

        
Self-check


        

          
1. Open WebUI shows an error that it can't reach any models. Which is the most useful first check?

          
          
          
          
          
Open WebUI is a client of Ollama. If it can't see models, the question is whether the
          Ollama server on port 11434 is up and has models pulled.

        


        

          
2. What does ollama pull qwen3:8b do?

          
          
          
          
          
pull only fetches and stores the model. run is what loads it
          into memory and starts talking to it.

        


        

          
3. You're low on disk. You run ollama rm qwen3:8b. What happened?

          
          
          
          
          
rm removes one model's files and nothing else. The server, the app, and
          your chats are untouched, and ollama pull brings the model back.
