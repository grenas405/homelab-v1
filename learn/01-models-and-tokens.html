What the machine thinks in

Before you can reason about speed, memory, or model choice, it helps to know what a language model actually is and what a "token" is. This plate is the vocabulary the rest of the handbook leans on.

A model is a big pile of numbers

A language model is a file full of numbers called parameters (also called weights). qwen3:8b has about 8 billion of them — that's what the 8b means. Each parameter is a small dial that was tuned during training so that, given some text, the model produces a sensible guess at what comes next.

That is the whole trick. The model reads the conversation so far and predicts the next chunk of text, then the next, then the next, one chunk at a time, until it decides to stop. Everything it "knows" is baked into those 8 billion dials. It is not looking anything up, and after setup.sh runs, it is not connected to anything.

Why the parameter count matters More parameters generally means better answers, but the file gets bigger and every predicted chunk takes more arithmetic — so it runs slower and needs more memory. Plate 04 turns this into numbers.

Text goes in as tokens

The model doesn't see letters or words. Text is first chopped into tokens — pieces that are often a whole short word, sometimes part of a longer word, sometimes just punctuation or a space. A rough rule for English is one token per ~4 characters, or about 0.75 tokens per word.

The context window is the desk

Everything the model can look at right now — the system prompt, the conversation so far, the documents you pasted, and the reply it's currently writing — has to fit inside its context window, measured in tokens. Think of it as the size of the desk. When the desk is full, the oldest papers fall off the back: early parts of a long conversation stop influencing the answer.

A model with an 8,000-token window can hold very roughly 6,000 words of combined prompt and reply. Longer windows exist; they cost more memory and slow generation down, because the model re-reads the whole desk for every chunk it writes.

Quantization trades precision for room

Each parameter is stored as a number. Store it at full precision (16 bits) and an 8-billion-parameter model needs about 16 GB just to sit in memory. Quantization rounds those numbers to fewer bits so the file shrinks. The common setting is Q4 — roughly 4 bits per parameter.

PrecisionBits / paramSize of an 8B modelQuality
FP1616~16 GBreference
Q88~8.5 GBpractically identical
Q4~4.5~5–6 GBvery close; the usual choice
Q2~2.5~3.5 GBnoticeably worse; last resort

When you run ollama pull qwen3:8b, you get a Q4 build by default. That's why the download is around 5 GB and not 16. Plate 04 uses these sizes to work out what fits on your GPU.

The one-line version A model predicts the next token. Tokens are ~4 characters. The context window is how many tokens it can see at once. Quantization shrinks the model by storing each parameter in fewer bits, trading a little quality for a lot of room.

Self-check

1. What does the 8b in qwen3:8b refer to?

Parameters are the tuned numbers inside the model. Disk size and context window are separate things that happen to also be measured in gigabytes and thousands.

2. You paste a 1,200-word document into the chat. Roughly how many tokens is that?

Around 0.75 tokens per word, so 1,200 × 0.75 ≈ 900. That has to share the context window with the system prompt, the rest of the conversation, and the reply.

3. Why is the default qwen3:8b download about 5 GB rather than 16 GB?

Q4 stores each parameter in about a quarter of the bits of FP16, so the file is roughly a third of the size, for a small quality cost.
